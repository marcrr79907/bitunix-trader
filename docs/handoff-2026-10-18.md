## Flujo de trabajo (SIEMPRE seguir)

- **SDD por OpenSpec**: cada change = `openspec/changes/<name>/`
  (explore → proposal → spec/design → tasks → apply → verify → archive).
  Ejecutar vía subagentes `sdd-*`; el orquestador **no toca `openspec/**` durante apply**
  (lo reconcilia el archive).
- **Cadena de PRs** (`feature-branch-chain`): tracker branch → slices (todas las bases =
  tracker; mergear cada slice al tracker ANTES de la siguiente) → tracker → `develop`.
  `main` no se toca.
- **Rama nueva ANTES de editar**. Commits convencionales, sin atribución AI.
- **Slices**: si el forecast supera ~400 líneas por slice, **partirlo** (F9 y F10 fueron a
  5 slices). Verificar que cada slice pase los gates solo.
- **Gates**: `node --test "tests/js/**/*.test.js"` · `pytest -p no:randomly` · `ruff check` +
  `format --check` · `makemigrations --check` · patch 100% (diff-cover vs `origin/develop`).
  Usar `.venv/bin/{python,ruff}`.
- **Push**: `GIT_TERMINAL_PROMPT=0`.
- **Calidad**: después de aplicar → `sdd-verify` + fresh review adversarial +
  `/impeccable` (obligatorio para features con UI). Esto atrapó defectos reales en
  F6, F7, F9 y F10 que los gates verdes no veían.

## Gotchas aprendidos (críticos)

1. **Techo de 300 líneas por módulo JS** (`tests/web/test_module_size_guard.py`, allowlist VACÍA):
   NUNCA dejar un módulo en 300/300 — extraer antes de agregar. Estado actual:
   `controllers/smc.js`=300 · `main.js`=293 · `drawing-interaction.js`=291 ·
   `drawing-interaction-core.js`=285 · `drawing-tools-core.js`=284 · `drawings.js`=282 ·
   `alerts.js`=278.
2. **`window.marketChart` = 8 keys congeladas. `STORE_KEYS` = 11 congeladas** (no agregar).
3. **#68 single-write-path**: live → `update()`; history/config → `setData()`;
   dibujos/medida/posición/marcadores → **primitive** (`requestUpdate`), jamás `setData`/`update`.
4. **R14**: todo acceso a modelos owned va por `for_user` en el request path
   (lectura unscoped SOLO en `web/worker.py`).
5. **Migraciones de `choices`**: son choices-only `AlterField`, reversibles, sin cambio de
   columna (`0015` position, `0016` F9 kinds).
6. **`CANDLE_INTERVALS`** (8: 5m,15m,1h,2h,4h,1d,1w,1M) es lo único que el worker evalúa —
   alertas en 1m/3d/6h/8h/12h nunca disparan.
7. **Colores de canvas**: leer tokens con `theme-core.token(name, fallback)` y re-renderizar
   en el callback de tema (`onTheme`); nunca literales hard-coded (rompen el tema claro).
8. **Cuando la spec y el design se contradicen, la SPEC es normativa** — corregir el código,
   y corregir el test que codificaba el comportamiento viejo.
9. **Tests que construyen su propio `map` sintético** pueden enmascarar bugs de producción
   (F9 `ray`); usar el map real del primitive.
10. **`git add -A` mete `openspec/` y artefactos** en commits de código — stagear selectivo.
    `cov.xml` ya está en `.gitignore`.
11. **E2E es dev-only** (`-m e2e -p no:randomly`) y tiene un flake clase C (#149) por SQLite
    threaded; CI no corre E2E. Verificar por DOM + red capturada, nunca píxeles.
12. **Los subagentes de review/verify timeoutean** por red a veces → verificar inline con
    evidencia directa (grep/wc/tests) y seguir.
