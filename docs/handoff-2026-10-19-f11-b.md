## Flujo de trabajo (SIEMPRE seguir)

- **SDD por OpenSpec**: `openspec/changes/<name>/` (explore → proposal → spec/design → tasks → apply → verify → archive).
- **Cadena de PRs** (`feature-branch-chain`): tracker → slices → tracker → `develop`.
- **Rama nueva ANTES de editar**. Commits convencionales, sin atribución AI.
- **Slices ≤400 líneas, MEDIDAS**:
  `git diff --numstat <base>..<head> -- web src tests | awk '{a+=$1;d+=$2} END {print a+d}'`.
  Si te pasás, partí el commit (se hizo dos veces en F11-B: 460 → 197+289, y 485 → 373+134).
- **Gates**: `node --test "tests/js/**/*.test.js"` · `pytest -p no:randomly` ·
  `ruff check` + `format --check` · `makemigrations --check` · patch 100% (diff-cover).
  Usar `.venv/bin/{python,ruff}`.
- **Calidad**: `sdd-verify` + review adversarial fresco + `impeccable detect --json <files>`
  y auditoría manual (obligatorio si hay UI).
- **Push**: `GIT_TERMINAL_PROMPT=0`.

## Gotchas aprendidos (críticos)

1. **NUNCA `gh pr merge --delete-branch` en una cadena apilada.** Borra la rama BASE y
   GitHub auto-cierra los PRs downstream (pasó en F11-A: #240/#242/#244). En F11-B se
   mergeó sin `--delete-branch` y funcionó. Borrá ramas solo al final, y solo las locales
   + las remotas ya mergeadas.
2. **En una cadena apilada, el merge va a la base, no al tracker.** Después de mergear
   #250 (base=tracker) el tracker NO tenía los slices. El PR final a `develop` se abrió
   desde la rama que contenía la cadena completa (`s3`), tras verificar
   `git diff <tree-validado>` == 0.
3. **Techo de 300 líneas por módulo JS** (allowlist VACÍA): `controllers/smc.js`=**300**
   (sin margen) · `main.js`=**297** (sin margen práctico) · `controllers/templates.js`=197.
   **Cualquier feature nueva en el chart debe ir en un controller/core nuevo, no en `main.js`.**
4. **`window.marketChart` = 8 keys congeladas. `STORE_KEYS` = 11 congeladas.**
5. **#68 single-write-path**: live → `update()`; history/config → `setData()`;
   overlays → primitive; **templates → reusan `indicator:changed` + `layout:loaded`**.
6. **R14**: modelos owned → `for_user` en el request path. Ojo: `for_user(...).create()`
   **filtra, no inyecta** el owner — pasalo explícito: `for_user(u).create(user=u, ...)`.
   El guard (`test_owned_model_guard.py`) exige la forma `for_user(...)`.
7. **Tests de migración deben ser agnósticos al leaf**: `test_migration_0016` asumía
   "última migración"; ahora usa `>= "0016"`. Todo test nuevo de migración debe tolerar
   migraciones posteriores.
8. **Alertas leen SOLO DB** (`run_alert_rules` → `_db_rows`). Un par sin ingesta nunca
   dispara; la ingesta cubre `config.SYMBOLS` + watchlists (cap 50).
9. **Presupuesto de requests**: `due_intervals` mantiene 50 símbolos en ~0.25 req/s
   (límite 10). Si agregás símbolos/intervalos, re-correr los asserts en
   `tests/web/test_worker_candles.py`.
10. **No se backfillea historial** a SQLite. El chart pide al upstream vía `_fetch_window`.
11. **Cuando la spec y el design se contradicen, la SPEC es normativa.**
12. **`git add -A` mete `openspec/`** en commits de código — stagear selectivo.
13. **Diálogos**: validar en `submit` con `preventDefault()`, NUNCA en `close`. Un error
    escrito a un diálogo cerrado es invisible (bug repetido en F10 y F11-B).
14. **a11y de color**: `--up` sobre superficie clara = 4.36:1 (bajo AA). Usar `--text` +
    peso, o verificar con el helper de `tests/web/test_market_ux.py`.
15. **E2E es dev-only** (`-m e2e`) y tiene flake #149 por SQLite threaded; CI no lo corre.
16. **Los subagentes SDD timeoutean por red** (5 de 6 en la sesión de F11-A/B). Verificar
    si el archivo existe; si no, hacerlo inline con evidencia directa. No reintentar más
    de una vez.
