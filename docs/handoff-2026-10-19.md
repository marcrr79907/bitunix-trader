## Flujo de trabajo (SIEMPRE seguir)

- **SDD por OpenSpec**: cada change = `openspec/changes/<name>/`
  (explore → proposal → spec/design → tasks → apply → verify → archive).
- **Cadena de PRs** (`feature-branch-chain`): tracker branch → slices → tracker → `develop`.
  `main` no se toca.
- **Rama nueva ANTES de editar**. Commits convencionales, sin atribución AI.
- **Slices**: si el forecast supera ~400 líneas, partirlo. **Medir, no estimar**:
  `git diff --numstat <base>..<head> | awk '{a+=$1;d+=$2} END {print a+d}'`.
- **Gates**: `node --test "tests/js/**/*.test.js"` · `pytest -p no:randomly` ·
  `ruff check` + `format --check` · `makemigrations --check` · patch 100% (diff-cover).
  Usar `.venv/bin/{python,ruff}`.
- **Calidad**: después de aplicar → `sdd-verify` + fresh review adversarial +
  `/impeccable` (obligatorio si hay UI) + `impeccable detect --json <files>`.
- **Push**: `GIT_TERMINAL_PROMPT=0`.

## Gotchas aprendidos (críticos)

1. **`gh pr merge --delete-branch` en una cadena apilada DESTRUYE la cadena.** Borra la
   rama **base** del PR mergeado, y GitHub auto-cierra todos los PRs downstream que
   apuntaban a ella. Pasó con #240/#242/#244 (quedaron CLOSED sin merge). Recuperación:
   la cadena lineal estaba intacta en la rama `review`; verificar `git diff <tree-validado>`
   == 0 líneas y bajar un único PR con todo. **NUNCA pasar `--delete-branch` hasta que
   toda la cadena lande.** (El merge del tracker a `develop` tampoco debe borrar ramas
   hasta el final.)
2. **Techo de 300 líneas por módulo JS** (`tests/web/test_module_size_guard.py`, allowlist VACÍA):
   `controllers/smc.js`=300 · `main.js`=**295** (no crecer más) · `controllers/symbol-picker.js`=207.
3. **`window.marketChart` = 8 keys congeladas. `STORE_KEYS` = 11 congeladas** (no agregar).
4. **#68 single-write-path**: live → `update()`; history/config → `setData()`;
   overlays → primitive (`requestUpdate`), jamás `setData`/`update`.
5. **R14**: todo acceso a modelos owned va por `for_user` en el request path
   (lectura unscoped SOLO en `web/worker.py`).
6. **Alertas leen SOLO DB** (`run_alert_rules` → `_db_rows`). Un par sin ingesta nunca
   dispara. La ingesta cubre `config.SYMBOLS` + watchlists (cap 50).
7. **Presupuesto de requests**: 8 intervalos × 50 símbolos / 30s = 13.3 req/s > 10 req/s
   del exchange. `due_intervals` lo baja a ~0.25 req/s. Si agregás símbolos o intervalos,
   re-verificá con los asserts en `tests/web/test_worker_candles.py`.
8. **No se backfillea historial** a SQLite (decisión del owner). El chart pide al upstream
   vía `_fetch_window`; el worker solo persiste velas cerradas (~424 filas/símbolo/día).
9. **Cuando la spec y el design se contradicen, la SPEC es normativa.**
10. **`git add -A` mete `openspec/`** en commits de código — stagear selectivo.
11. **E2E es dev-only** (`-m e2e -p no:randomly`) y tiene un flake clase C (#149) por SQLite
    threaded; CI no corre E2E. Verificar por DOM + red capturada, nunca píxeles.
12. **Los subagentes SDD timeoutean por red** (4 de 5 en la sesión de F11-A: explore,
    design, review, proposal). Verificar si el archivo existe; si no, hacerlo **inline**
    con evidencia directa (grep/wc/tests) y seguir. No reintentar más de una vez.
13. **a11y de color**: `--up` sobre superficie clara da **4.36:1** (bajo AA 4.5).
    Usar `--text` + peso, o verificar contraste con el helper de
    `tests/web/test_market_ux.py` antes de elegir un token.
